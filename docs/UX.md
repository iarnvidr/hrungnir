# Hrungnir UX

## Product boundary

The app is **Hrungnir**, a native local reader with a compact classic Reddit inspired layout. The subreddit heading keeps its post count beside the title, with sort and **Fetch all media** controls on the same compact row when space allows. Listing rows use a small local thumbnail when one is available, otherwise a type mark; only validated local asset URLs are assigned to image elements. Retention details live in Settings rather than a persistent listing banner. Separate **Subreddits & posts** and **Post reader** tabs keep browsing and reading distinct; both show local UI only, never a remote Reddit page. The reader holds multiple independently closeable post tabs. The **＋ New tab** action and Cmd/Ctrl+T add a visible, transient “New subreddit search” tab and focus the subreddit field in **Subreddits & posts**. Cmd/Ctrl+W closes that draft first, then closes the active post tab, and prevents the native window-close default. Selecting a post resolves the draft into its regular post tab. The post-tab strip stays visible across sections and hides its horizontal scrollbar while retaining trackpad/touch scrolling, visible keyboard focus, and arrow-key navigation that scrolls the selected tab into view. Drafts are not persisted between app launches. The subreddit list can be ordered by recent, favorites, or alphabetically. Tab selection, open post IDs and comment anchors, favorites, recents, listing ID order, sort, independent reader text and element scale, reader media presentation, theme, and accent are UI preferences stored in `localStorage`; post and comment content remains in SQLite and media bytes remain in the media cache. Text scale is bounded to 85–140%; element scale is bounded to 85–125%. Theme, accent, media presentation, and reader scales live in the **Settings** dialog. It offers **System**, **Classified dark**, and **Classified light**, with blue/red/amber/teal accents. System follows OS light/dark mode; Classified modes use local Inter, Cinzel, and IBM Plex Mono fonts. Theme design details are in [DESIGN.md](DESIGN.md).

The global header has one search field. Typing immediately queries the local cache through `search_cache({query, subreddit: null, limit: 50})` and shows matching saved posts and comments in a dropdown; typing never contacts Reddit or fetches a source. New keystrokes supersede older cache replies. Enter or **Search** cancels pending local work and calls `search_reddit({query, subreddit: null, sort: 'relevance', period: 'all'})`; a late local reply cannot reopen the dropdown over live results. Reddit results appear in the main post listing with relevance/new/top/comments sorting and an optional time period for every search sort. Changing sort or period reruns that query. Results can span subreddits and retain their own listing context while a selected post loads. Choosing a cached dropdown hit calls read-only `open_cached_thread({id})`, then opens the saved post in a tab and restores the matching comment anchor; this action stays cached-only and does not submit a Reddit search or fetch missing content. Clear and Escape cancel pending work and restore the previous listing. Diagnostics retain only query character counts, never the query text. A search-opened tab persists a cached-only flag so selecting it again or restoring it after restart calls `open_cached_thread` only. A listing-only cache entry is explicitly labeled **Cached listing; comments were not downloaded**. It does not call `fetch_thread` or acquire media; selecting that post from a subreddit listing is the explicit normal fetch path.

The **Library** tab searches saved posts and comments through debounced native `search_saved_library({query, limit: 100})` full-text search. It keeps the returned relevance order and applies the collection/type filters afterward. Empty search shows all saved items; the global header search remains separate. Comment hits open the cached post at the matching comment anchor. Article/video/image hits open their full saved content in Library detail. Library search is device-local and unavailable outside the native app. The tab's `library_state()` rows contain summary-only post bodies (first 2,000 characters), no comment bodies, and a `cached_comments` count; it does not bulk-load discussions. Opening any saved item calls `open_cached_thread({id})` for full cached content. Saved posts enter the existing reader tab as cached-only tabs, preserving their no-source-fetch behavior when reselected or restored. Standalone saved articles render their stored plain-text body and local media in Library detail; there is no raw remote HTML or direct remote UI load. **Save post** stores the current post with a collection and optional Keep forever policy. The Library's collapsed **Add linked content…** form accepts one explicit public URL even when no post is open; it offers article/video/image type, collection, and Keep forever (checked for new items). The reader's **Save linked content…** action switches to Library, opens the form, and prefills the current post's link URL. Native acquisition completes before the item appears in the saved library. Library ZIP import/export uses native file dialogs; cancellation is a no-op. Cache pruning says it removes unprotected cached post text, while saved Keep forever items and protected groups remain; it does not claim to delete media.

Settings includes native-persisted **Subreddit groups**. A group assigns subreddit names and post/unwatched-media and watched-media retention periods; selecting **Keep forever** stores a `null` lifetime. The Subreddits sidebar can filter by group. Group changes and Library metadata are read from `library_state()` and written through the native group and saved-item commands, not browser preferences. Each video in the reader and inline listing media has a **Keep video** action. It saves the post with `keep_forever: true`, preserving an existing collection (or using **Videos** for a new Library row), and protects the post plus completed media. The button displays **Kept forever** from the saved post row's `keep_forever` state; operation errors stay beside the player without rebuilding it.

The **Settings → Post cache** control reads and updates the native `post_cache_hours` setting through `get_cache_settings` and `set_cache_settings`. It accepts whole hours from 1 through 8760, with a native default of 48 hours. Saving refreshes the local snapshot, retains open tabs for posts that remain cached, and marks posts removed by the new lifetime as unavailable. The configured lifetime starts at post capture for post/comment content and at completed download for unwatched media. Videos played to at least 95% use their separate 24-hour default after completion. Subreddit group overrides apply to both timers, and Keep forever protects the post and completed media; the media budget may expire unprotected files earlier under storage pressure. **Fetch all media** explains that downloaded files follow these rules.

External Reddit links are delivered to the native queue as `AppLink` records. The frontend listens to `hrungnir-app-links` only as a wakeup, then drains `take_app_links` sequentially after startup cache and tab restoration completes; queued links are also drained at startup, with no polling. Subreddit links apply their sort and top period, switch to **Subreddits & posts**, and use the normal subreddit fetch flow. Post links call `open_link_post({url})`, merge the returned `ThreadDownload` without reordering subreddit listings, then open the reader tab and supplied comment anchor. Dialogs close before routing. The frontend checks the canonical `https://www.reddit.com/r/...` shape and native code validates it again. The standalone page has no app-link listener or native command path.

Entering a subreddit and choosing **Fetch posts** calls `fetch_subreddit({subreddit, sort, top_period})`, using the backend's snake_case argument for `top_period`. Sort values are `hot | new | top | rising`, and time periods are `hour | day | week | month | year | all`; defaults are `hot` and `day`. Changing the post sort refetches the active subreddit; changing the top period refetches only when sort is **Top**. The source listing's returned IDs and order are kept independently for each subreddit. A `fetch_thread` response updates matching cached post data without replacing the current listing order or another subreddit’s listing. A post click or post-tab activation checks an in-memory ready result with `validate_cached_media({id})`; a valid disk-cache hit opens immediately, while an evicted or missing asset triggers `fetch_thread({id})` before display. Concurrent validation and fetch requests share one per-post in-flight operation.

`ThreadDownload` contains `{snapshot, media}`. The reader renders the returned post and comment hierarchy as text, and renders media only through local URLs. It accepts the legacy Tauri asset URL and the tokenized loopback HTTP form `http://127.0.0.1:<port>/<64-hex-token>/t3_<id>/<filename>`; all other media origins and path shapes are rejected. The native app CSP must allow `127.0.0.1:*` for image and media sources. The loopback server exposes completed media only and supports byte ranges for playback. Images display locally; audio and video have native playback controls, no autoplay, and no remote fallback. Video height is capped to the viewport minus room for reader controls, adjusted for UI scale; its aspect ratio is preserved with no cropping. Reader media can be inline or collapsed. For ordinary outbound links outside Reddit, each listing row offers **Expand article** and **Open link**; Reddit post and self-post URLs do not get article controls. Expansion calls `fetch_link_article({id})` and renders its `{title, body, url}` as escaped text in the row, with explicit **Open original link** fallback. HTTPS URLs in post, comment, parent-preview, saved-article, and linked-article text become inline buttons that open only after a click; the reader builds them from text nodes and never parses user content as HTML. **Open link** calls `open_web_link({url})` to show the destination in an isolated native browser window. Linked image, audio, and video candidates continue to use the media controls. Reader media cards also offer **Open original link** when the post has an external source URL. Snapshots carry `link_previews[id] = {kind, domain, thumbnail}` with any cached local thumbnail. After each accepted snapshot, the reader requests missing previews through `fetch_link_previews({ids})` in batches of at most 100 without waiting for the listing render. It deduplicates pending and completed IDs and patches only the matching `[data-preview-for="id"]` thumbnail node; it never rebuilds the list or interrupts a playing media card. The thumbnail is displayed only when it passes the same local-asset URL validation used by cached media. A source listing's `media_hints` map gives each candidate post a conservative `kind` and count without exposing URLs. An omitted hint for a post in an incoming snapshot clears its stale candidate cue; hints for IDs absent from that snapshot remain. Known local assets are labeled **Cached** by their actual asset kind. Only hinted or already-cached posts get a typed **Load** or **Show** inline control. Clicking it awaits `fetch_thread` before displaying available local media; it never loads media directly from the listing or starts playback. **Fetch all media** applies only to media-hinted or already-cached posts in the currently loaded listing, never to more subreddit posts. It runs at most two `fetch_thread` operations at once, expands each matching card inline, reports completed/total/active/failure counts, and lets the user cancel queued work while current downloads finish. Failed rows retain their own **Retry** action. Each result updates its card in place so later completions do not rebuild the listing or interrupt a playing video. The fetch command completes media acquisition before returning, subject to the independent 512 MiB cache and 128 MiB per-file limits. Images and MP4s use direct downloads; approved stream sources use the bundled yt-dlp/ffmpeg tools. Download progress is represented by the awaited command's in-reader loading message; the reader does not poll a download-status command.

If a thread request fails, the current article remains visible, the requested row returns to idle, and a **Retry** action repeats `fetch_thread`. A successful thread response with `comments_status: "not_loaded"` is rejected as incomplete. Legacy `partial_browser` and current `partial_proxy` comments are shown with an explicit note that additional replies may be unavailable. When no comments are returned after a completed fetch, the reader says no comments were found.

The frontend uses `window.__TAURI__.core.invoke` for `fetch_subreddit`, `fetch_thread`, `fetch_link_previews`, `fetch_link_article`, `open_web_link`, `open_link_post`, `open_cached_thread`, `search_cache`, `get_cache_settings`, `set_cache_settings`, `take_app_links`, `validate_cached_media`, `app_diagnostics`, `snapshot`, `save_position`, `prune_cache`, `export_support_bundle`, `record_client_event`, and the existing import commands. On macOS only, Diagnostics shows **Allow proxy certificate…** when `report.platform.os` is `macos` and `report.source.trust_recovery.available` is true. The explanation says this adds Hrungnir's own `www.reddit.com` SSL certificate to the user's login Keychain and macOS may request confirmation. The reader invokes `trust_source_certificate` only after the user presses the button; the native command owns the explicit confirmation. Cancel reports that no certificate was added. Success says to fetch posts again and does not claim that TLS is connected. If known macOS diagnostics show TLS failures with no successful TLS handshakes, a subreddit fetch error points the user to Diagnostics. There is no automatic retry or installation.

The **Diagnostics** dialog shows the `app_diagnostics().report` recent operation list and an in-reader performance summary. During longer acquisitions it polls `report.active_operations` to show stage and elapsed time. **Export support ZIP** calls the native save-dialog command and reports cancel/success/error with the returned file path, size, and event count. Copyable JSON and an optional JSON-file export remain available. Bounded browser telemetry reports operation names, elapsed duration and item counts; playback lifecycle samples include only numeric ready/network/time/error codes and theme/accent labels. Sampling is capped and excludes URLs, subreddit names, post/comment text, and freeform errors. Selected-post snapshots merge by ID into the existing cache and listing. Playback errors invalidate the in-memory media-ready marker; the reader waits for user retry instead of automatically repeating a download.

Advanced controls retain fixture and JSON import plus local cache clearing. They do not simulate Reddit or media acquisition. The standalone HTML has no mock fallback or content persistence; theme and other UI preferences are stored locally. Without the Tauri bridge, content operations are disabled with a native-app message. User content is inserted as text, never HTML.

## Context

The classic-reader design takes its cues from a Firefox setup using Old Reddit Redirect, RES night mode and previews, and uBlock cosmetic filters. Live appearance and hostname behavior were not verified, and no browser profile or credentials are read. Recreate useful classic-reader behavior deliberately without assuming the native app has Firefox extensions.

The standalone [`preview/index.html`](../preview/index.html) remains a synthetic UX fixture. It demonstrates compact list/detail reading, nested comment expansion and parent previews, keyboard concepts, and hypothetical subreddit/group policies. Its cache badges and policy controls are presentation only; they are not implemented app functions.
